\begin{abstract}
Vision-language-action (VLA) policies often amortize expensive inference by predicting action chunks, but later actions in a chunk are executed under observations that may no longer match the current robot state. We introduce \method{}, a narrow intervention that keeps a LIBERO-adapted \smolvla{} planner frozen and trains only a small wrist-camera residual module for the action currently being executed. The fast module uses current wrist patch features, proprioceptive state, the selected base action, chunk position, and cached slow-planner context, then applies the bounded merge $\afinal=\abase+\alpha\,\mathrm{clip}(\deltah)$. All main quantitative claims are LIBERO-Spatial only. In synchronous plan-50 execution sweeps, \method{} reaches $79,80,71,75,59,53\%$ success at $K=2,4,8,16,32,50$, while \smolvla{} reaches $72,65,60,57,50,40\%$; at $K=1$, \method{} is lower ($75\%$ versus $79\%$). In synchronous matched-chunk sweeps, \method{} improves from $K=4$ onward and reaches $53\%$ versus $40\%$ at $K=50$. A residual calibration sweep shows that bounded residual authority matters, with $\alpha=0.75,\dmax=0.2$ achieving $41/50$ Spatial successes in the plan-50, exec-8 calibration setting. Finally, a planner-delay stress test shows that with delay $d=1..4$, \method{} maintains $68,72,68,66\%$ success while a disable-fast ablation drops to $64,62,61,56\%$. These results support \method{} as a clipped local correction layer for stale VLA chunks, not as a replacement for frequent replanning or full async VLA scheduling.
\end{abstract}

\section{Introduction}

Large robot policies increasingly combine language-conditioned task intent, visual grounding, and continuous action generation. RT-1, RT-2, Open X-Embodiment/RT-X, OpenVLA, Octo, $\pi_0$, and \smolvla{} show that large pretrained or cross-embodiment policies can become broadly useful robot controllers~\citep{brohan2022rt1,brohan2023rt2,openx2024,kim2024openvla,ghosh2024octo,black2024pi0,shukor2025smolvla}. Their deployment bottleneck is timing. Running the slow policy every control tick is expensive, so many systems emit multi-step action chunks and execute several actions before replanning.

Chunking creates a stale-action failure mode. The first action in a chunk is conditioned on the observation that produced it; later actions may be executed after the gripper, object, or contact geometry has shifted. This mismatch is especially visible in Spatial manipulation tasks, where small gripper-relative errors can flip success. The slow planner may still have the correct global task intent, but the local action should be corrected from current evidence near the wrist.

\method{} tests this idea under a constrained contract. We use a LIBERO-adapted \smolvla{} model as the frozen planner, cache its base actions and slow context, and train only a small wrist residual head. The per-step visual correction signal is wrist-camera based. The residual is not a wrist-only controller: it also conditions on $\abase$, chunk position, robot state, and slow-planner context. It is also not a complete real-time VLA scheduler. It is a fast local correction module wrapped around a frozen chunking controller.

The current first-draft evidence is deliberately scoped. Main quantitative claims are LIBERO-Spatial only; Object results are not combined into the main text. All sweeps except the planner-delay experiment use synchronous inference; only the planner-delay sweep uses async-timestep inference. Figures carry the primary evidence, and compact tables report exact values.

The contributions are:
\begin{itemize}
  \item A LeRobot-based frozen-\smolvla{} system with a trainable wrist-camera residual correction path.
  \item A clipped residual merge, $\afinal=\abase+\alpha\,\mathrm{clip}(\deltah)$, that avoids slow-planner fine-tuning, a learned deployment gate, or a contact auxiliary head.
  \item Spatial-only planning/execution sweeps that separate fixed plan-50 execution from matched planning/execution chunks.
  \item An async-timestep planner-delay stress test showing that the fast residual mitigates degradation when slow chunks arrive late.
\end{itemize}

\section{Related Work}

\paragraph{VLA and generalist robot policies.}
Large-scale robot policies range from transformer controllers trained on real robot data~\citep{brohan2022rt1} to VLAs that co-train web-scale vision-language models with robot actions~\citep{brohan2023rt2,kim2024openvla,black2024pi0,shukor2025smolvla}. Open X-Embodiment and DROID highlight the data-scaling side of this trend~\citep{openx2024,khazatsky2024droid}, while Octo studies an open generalist controller that can adapt across sensors and action spaces~\citep{ghosh2024octo}. \method{} does not train a new foundation model. It asks whether a frozen VLA chunk can be corrected locally.

\paragraph{Action chunking and real-time execution.}
Action Chunking Transformers and Diffusion Policy helped establish chunked action generation and receding-horizon execution in manipulation~\citep{zhao2023aloha,chi2023diffusionpolicy}. FAST studies action tokenization for high-frequency VLA action sequences~\citep{pertsch2025fast}. More recent real-time VLA work addresses latency and chunk continuity: RTC executes one chunk while generating the next~\citep{black2025rtc}, VLASH predicts future execution-time state~\citep{tang2025vlash}, and VLA-RAIL links asynchronous VLA chunks into smoother robot trajectories~\citep{zhao2025vlarail}. \method{} is complementary: it leaves scheduling mostly untouched and corrects the action being executed.

\paragraph{Correction heads and fast-slow policies.}
A2C2 is the closest conceptual reference: it adds a lightweight correction head to off-the-shelf VLA chunks using the latest observation, base action, chunk index, and base-policy features~\citep{sendai2025a2c2}. Other fast-slow systems integrate fast manipulation pathways into slower reasoning or foundation-model controllers~\citep{chen2025fastinslow,zou2025duocorefs,xue2025rdp,xie2026dynamicvla}. \method{} follows the frozen-chunk correction philosophy but isolates a wrist-centric residual path in a \smolvla{}/LeRobot implementation~\citep{cadene2026lerobot}. We do not claim a direct comparison to A2C2 without matching backbone, observation stack, data, and evaluation scripts.

\paragraph{Wrist views and dense visual features.}
Wrist and egocentric views provide local evidence for precision manipulation~\citep{jangir2022lookcloser,chuang2024activevision}. Dense self-supervised ViT features expose localized visual structure, as shown by DINO, DINOv2, DINOv3, and dense descriptor analyses~\citep{caron2021dino,oquab2023dinov2,simeoni2025dinov3,amir2021densevit}. Robot systems such as R3M, DINOBot, and CAGE further motivate using pretrained visual features for data-efficient manipulation~\citep{nair2023r3m,dipalo2024dinobot,xia2024cage}. \method{} uses frozen DINOv3 wrist patches as inputs to the residual head: a $224\times224$ wrist crop produces a $14\times14$ patch grid, stored as 196 patch tokens with 384 channels. These tokens preserve local image structure for cross-attention pooling; heatmaps are treated as diagnostics unless paired with causal ablations.

\section{Method}

\subsection{Problem Setting}

Let a frozen VLA planner produce an action chunk from observation $o_t$ and language instruction $\ell$:
\begin{equation}
  A_t = (a^0_t, a^1_t, \ldots, a^{H-1}_t).
\end{equation}
At execution time the robot selects a base action $\abase \in \mathbb{R}^7$ from the active chunk. The correction problem is to predict a bounded residual $\deltah\in\mathbb{R}^7$ from current wrist feedback and cached context while leaving the slow planner unchanged.

\subsection{Frozen Planner and Cached Context}

The slow planner is a LIBERO-adapted \smolvla{} model that remains frozen throughout training and evaluation. During dataset recording, the system stores the base action selected from the planner's chunk, the chunk position, compact slow-planner context, wrist DINOv3 patch features, robot state, images, and expert action. The verified cached dataset contains 1,693 episodes and 273,465 frames over 40 tasks. The fast module trains from these cached features, so training does not update or rerun the slow planner. If the slow planner or feature-extraction contract changes, the cache must be regenerated. Implementation identifiers and exact field names are reported in Appendix~\ref{app:implementation-reproducibility}.

\subsection{Wrist Patch Features}

The fast visual path uses the wrist camera rather than the third-person image as its high-frequency evidence source. During recording/cache construction, a frozen DINOv3 ViT-S/16 feature extractor maps each wrist frame to a $14\times14$ grid of 196 patch tokens with 384 channels per token. DINOv3 is not updated or rerun inside the fast-module training loop; training reads precomputed dense wrist descriptors. This keeps the trainable parameter budget isolated to the residual head and fixes the provenance of the visual features.

Although the cached descriptor is stored as a token sequence, it still corresponds to the wrist image's spatial grid. The residual head projects the tokens to its hidden width and pools them with a query conditioned on the selected base action, chunk position, robot state, and slow-planner context. Thus the wrist branch keeps local patch-level visual evidence while remaining anchored to the task and phase represented by the frozen planner. The diagnostic panel below visualizes one frame with third-person RGB, wrist RGB, DINO patch-norm heatmap, and FWR cross-attention. The visualization documents the signal path and spatial correspondence; it is not treated as causal evidence without the masking ablations listed in the appendix.

\subsection{Fast Wrist Residual}

The trainable module receives current wrist patch features, robot state, $\abase$, chunk position, cached slow-planner context, and a short previous/current training window. It predicts a full 7D residual $\deltah$ for the action about to be executed. Deployment uses:
\begin{equation}
  \afinal =
  \abase + \alpha \cdot \mathrm{clip}(\deltah, -\dmax, \dmax).
  \label{eq:merge}
\end{equation}
The current paper intentionally excludes the older learned gate, contact auxiliary objective, and GRU-centered deployment claim. Improvements must come from the residual and its conditioning, with bounded residual authority.

\begin{figure}[t]
  \centering
  \includegraphics[width=0.98\linewidth]{figures/fig1_solution_schematic.pdf}
  \caption{\method{} architecture. The frozen \smolvla{} planner follows the SmolVLA input contract: language, top-view RGB, wrist RGB, and robot state condition a VLM/action-expert stack that produces low-frequency base action chunks and cached slow context. A frozen DINOv3 wrist encoder and trainable fast residual module then use current wrist feedback, state, chunk context, and the selected base action to predict a bounded residual. The final action is formed by clipping and scaling the residual before adding it to the selected base action.}
  \label{fig:method}
\end{figure}

\subsection{Training Objective}

The supervised target is the expert residual:
\begin{equation}
  \Delta a^* = a_{\mathrm{expert}} - \abase,
\end{equation}
with loss
\begin{equation}
  \mathcal{L}_{\mathrm{res}} =
  \lVert \deltah - \Delta a^* \rVert_2^2.
\end{equation}
This target is simple, but it raises a stale-target question: deployment may correct an older chunk action, while training uses the simultaneous residual. Chunk-age targets are therefore listed as unfinished work in the appendix.

\section{Experiments}

\subsection{Protocol}

All quantitative claims are cross-checked against the project eval registry, which currently contains 267 registered rows. Main results use LIBERO-Spatial~\citep{liu2023libero} only with seed 42. The two synchronous generated-checkpoint sweeps use 100 episodes per row, 10 per LIBERO-Spatial task. Unless otherwise specified, the trained \method{} policy is evaluated with $\alpha=0.5$ and $\dmax=0.2$; the comparison baseline is the frozen \smolvla{} planner.

All sweeps except the planner-delay experiment use synchronous inference. Only the planner-delay sweep uses async-timestep inference. The three main protocols are:
\begin{itemize}
  \item \textbf{Plan-50 execution sweep:} planning chunk size is fixed at 50; execution/replan interval $K$ varies.
  \item \textbf{Matched chunk sweep:} planning, execution, and replan interval are all set to $K$.
  \item \textbf{Async planner-delay sweep:} planning chunk is 50, execution interval is 16, async request interval is 8, and artificial planner delay $d$ varies from 0 to 4.
\end{itemize}

\section{Results}

\subsection{Synchronous Plan-50 Execution}

Figure~\ref{fig:plan50} shows the plan-50 Spatial sweep. \method{} is below \smolvla{} at $K=1$ (75\% versus 79\%), where the planner refreshes every step. Once execution becomes less frequent, \method{} reaches $79,80,71,75,59,53\%$ success at $K=2,4,8,16,32,50$, while \smolvla{} reaches $72,65,60,57,50,40\%$. This is the main evidence for the stale-chunk correction claim.

  \caption{LIBERO-Spatial synchronous plan-50 execution sweep. Error bars show Wilson 95\% intervals for 100 episodes per row. The residual is harmful at $K=1$ but improves the frozen planner as execution/replan intervals grow.}
  \label{fig:plan50}
\end{figure}

\subsection{Synchronous Matched Chunk Sweep}

Figure~\ref{fig:matched} sets planning, execution, and replanning to the same $K$. The result is more conservative than the plan-50 sweep: \method{} underperforms at $K=1,2$, matches at neither short setting, then improves from $K=4$ onward. At $K=50$, \method{} reaches 53\% while \smolvla{} reaches 40\%. The result supports the local-reflex framing but also shows that long-horizon chunking remains hard.

  \label{fig:matched}
\end{figure}

\subsection{Residual Scale and Clipping}

Figure~\ref{fig:calibration} shows the Spatial residual calibration used for the plan-50, exec-8 setting. The best tested setting is $\alpha=0.75,\dmax=0.2$, with $41/50=82\%$ success. The broader calibration evidence also shows that residual authority must be bounded: in a separate long-chunk Spatial calibration at plan=exec=replan=50, no-limit settings with $\dmax=999$ drop to 16\%, 4\%, and 2\% for $\alpha=0.5,0.75,1.0$. Clipping is therefore part of the method, not a cosmetic safety setting.

  \label{fig:calibration}
\end{figure}

\subsection{Async Planner-Delay Stress Test}

The planner-delay experiment is the only async-timestep result in the paper. Here the slow planner observes at time $t$, its chunk becomes available after $d$ control timesteps, and execution starts at chunk index $d$. The fast wrist residual still runs at the current timestep. Figure~\ref{fig:delay} compares \method{} with a disable-fast ablation of the same wrapper. At $d=0$, disable-fast is higher (68\% versus 64\%). For delayed chunks, \method{} maintains $68,72,68,66\%$ success at $d=1,2,3,4$, while disable-fast drops to $64,62,61,56\%$.

\section{Discussion}

\paragraph{Why the residual helps stale chunks.}
The result pattern is consistent with a fast local correction story. When the frozen planner replans at every step, the base action is already aligned with the current observation and the residual can over-correct. As the active chunk ages, the wrist view provides current gripper-relative evidence that the base chunk lacks. The result is not a universal improvement; it is a regime-specific correction.

\paragraph{Why clipping is central.}
The residual head predicts a full 7D action correction. Without clipping, its authority can exceed the local errors it was meant to fix. The calibration results show that the merge rule is part of the algorithmic claim: the fast module is useful as a bounded correction layer, not as an unconstrained replacement action head.

\paragraph{What the async result does and does not prove.}
The async-timestep sweep isolates planner-latency semantics in simulation. It does not yet prove real-time deployment on a separate remote slow-planner server, nor does it cover arbitrary compute delays. It does show that current wrist feedback prevents the success degradation seen when the same wrapper disables the fast residual under delays $d=1..4$.

\section{Limitations}

The main evidence is single-seed LIBERO-Spatial simulation. Confidence intervals in the plots are binomial intervals over episodes, not multi-seed intervals. Real robot latency, camera calibration, actuation limits, contact dynamics, and residual cap settings may shift the residual distribution. The method also depends on the cached slow-planner contract: changing the slow planner or feature extraction requires re-recording cached base actions and context.

The wrist path is local. It can correct gripper-relative drift when the wrist camera sees relevant geometry, but it cannot replace global scene understanding when the target relation is outside the wrist view. Finally, the current training target is simultaneous rather than chunk-age aligned, so future training should explicitly model stale base actions.

\section{Conclusion}

\method{} asks whether a frozen VLA action chunk can be made more reactive by adding a small wrist-camera residual head. Spatial-only results support a precise claim: clipped wrist residuals help when chunks become stale, especially in longer execution intervals and async planner-delay settings, while they can hurt when the slow planner replans every step. The method is therefore best understood as a bounded local correction layer for frozen VLA chunks.

\section{Unfinished Experiments}

The following items are intentionally marked in red because they are not complete enough for main-text claims:
\begin{itemize}
  \item \textcolor{red}{Dual-view DINO fast residual ablation}: train a wrist + third-person image fast model.
  \item \textcolor{red}{Latent-context ablation}: remove $z_{\mathrm{goal}}/z_{\mathrm{phase}}$ from the residual head.
  \item \textcolor{red}{Chunk-age/stale-target training}: train residual targets against delayed base chunks.
  \item \textcolor{red}{No-residual-clip control sweeps}: expand the no-clip controls beyond current calibration evidence.
  \item \textcolor{red}{Multi-seed confidence intervals}: repeat the main sweeps across seeds or task-order variants.
  \item \textcolor{red}{Causal visual ablations}: wrist mask, third-person mask, and DINO patch masking.
  \item \textcolor{red}{Direct A2C2 same-backbone comparison}: reimplement A2C2 under the same \smolvla{} backbone and registry.
  \item \textcolor{red}{Real-robot tabletop validation}: run matched trials on a physical tabletop setup.
\end{itemize}

# AGENTS.md - HFRVLA Paper Workspace

Scope: this file applies to everything under `paper/`.

This folder contains multiple manuscript targets, shared research notes, build
outputs, templates, and agent-generated deliberation records. Do not treat the
entire directory as one paper.

## Core Layout

| Path | Purpose |
|---|---|
| `src/` | Buildable bilingual long-paper source. Keep `main.tex` and `main_zh.tex` synchronized when changing shared claims. |
| `targets/` | Target-specific manuscripts. Use this for NYCU thesis, conferences, journal versions, proposals, and defense-specific variants. |
| `targets/long_paper/` | Maintained dashboard for the long paper. Current buildable source remains `paper/src/main.tex` and `paper/src/main_zh.tex`. |
| `targets/nycu_thesis/` | Maintained NYCU master's thesis target. The current buildable source is `targets/nycu_thesis/latex/main.tex`. |
| `notes/` | Shared research notes that can feed multiple targets. These are not final manuscripts. |
| `deliberations/` | Outputs from academic skills, subagents, debate/review rounds, claim audits, citation audits, and decision records. |
| `templates/` | Raw external templates and template notes. Keep template archives here, not at paper root. |
| `thesis/` | Legacy thesis source and generated registry tables. Keep readable until all useful content is migrated to `targets/nycu_thesis/`. |
| `build/` | Workshop/arXiv build outputs. Do not hand-edit generated PDFs. |

## Source-Of-Truth Order

Use this order when resolving conflicts:

1. `experiments/eval_registry/eval_results_master.csv` for quantitative results.
2. `experiments/eval_registry/sources.csv` for result provenance.
3. `paper/notes/methodology_blueprint.md` for the shared method contract.
4. `paper/notes/research_questions.md` for active RQs and ablations.
5. `paper/notes/contribution_statement.md` for wording guardrails.
6. `paper/targets/<target>/README.md` for target-specific goals and claim boundaries.
7. Buildable LaTeX source under `paper/src/` or `paper/targets/<target>/`.

Never promote a claim from a generated PDF, old terminal output, or memory when
the registry or source notes disagree.

## Skill And Deliberation Outputs

When using academic-research, citation, paper-lookup, reviewer, or subagent
skills, store their durable outputs under `paper/deliberations/`.

Use this structure:

```text
paper/deliberations/
  shared/
    literature_searches/
    citation_audits/
    claim_audits/
    decision_logs/
  <target_name>/
    review_rounds/
    writer_reviews/
    methodology_reviews/
    rebuttal_plans/
    revision_logs/
```

For NYCU thesis, use:

```text
paper/deliberations/nycu_thesis/
```

Each deliberation note should include:

- Date.
- Skill, MCP, or subagent used.
- Input materials reviewed.
- Findings or debate positions.
- Decision made, if any.
- Follow-up edits performed.
- Remaining risks.

Do not put raw debate/review material directly in `src/`, `targets/<target>/latex/`,
or `notes/` unless it has been distilled into a stable source note.

## Literature And Citation Rules

- Use dedicated academic search or citation tools for new literature work:
  paper-lookup, Consensus, Zotero, DOI/arXiv/CrossRef/publisher pages, or
  official project pages.
- Prefer peer-reviewed robotics, vision, and ML venues when available. Recent
  preprints can be cited for emerging systems but must be labeled as preprints
  in notes and used conservatively.
- Add verified BibTeX to `paper/src/references.bib` first. Target-local copies
  such as `targets/nycu_thesis/latex/ref.bib` must be synchronized from there.
- Record search strategies, rejected sources, and citation audits under
  `paper/deliberations/shared/literature_searches/` or
  `paper/deliberations/shared/citation_audits/`.

## Results And Figures

- Rebuild/check the registry before changing numerical claims:

```bash
python3 scripts/build_eval_results_master.py --check
```

- Figures should be regenerated by scripts, not edited manually.
- Main text should report success rate first. Extra metrics belong in appendix
  or diagnostics unless they directly answer a research question.
- All sweeps except planner-delay are synchronous inference unless a protocol
  note explicitly says otherwise.
- The planner-delay sweep is async-timestep inference and must be described
  separately.

## Target Update Workflow

Before editing a target manuscript:

1. Read `paper/README.md`.
2. Read this `paper/AGENTS.md`.
3. Read `paper/targets/<target>/README.md`.
4. Check the target's `source_map.md`.
5. Verify any numerical claim against the eval registry.
6. Store reviewer/debate material under `paper/deliberations/<target>/`.
7. Edit buildable source only after the claim boundary is clear.
8. Run the target's build command.

Build commands:

```bash
# Long paper, English + Traditional Chinese
cd paper && bash build_bilingual.sh

# NYCU thesis target
cd paper/targets/nycu_thesis/latex && bash build.sh

# Legacy thesis, only when deliberately maintaining the old path
bash paper/thesis/build_thesis.sh
```

## NYCU Thesis Notes

- The local NYCU template archive lives at
  `paper/templates/nycu_thesis/NYCU_thesis_template__1_.zip`.
- The current NYCU-template LaTeX source lives at
  `paper/targets/nycu_thesis/latex/main.tex`.
- The generated NYCU PDF is
  `paper/targets/nycu_thesis/latex/build/main.pdf`.
- Administrative fields such as advisor, department, official degree name, and
  defense date must remain placeholders until confirmed.

## Manuscript Split

Maintain the long paper and NYCU thesis separately at the manuscript level. They
share notes, registry-backed results, figures, and bibliography entries, but
their LaTeX source and narrative depth should remain separate:

- Long paper: concise claim-driven manuscript in `paper/src/`, controlled by
  `paper/targets/long_paper/README.md`.
- NYCU thesis: degree-oriented manuscript in
  `paper/targets/nycu_thesis/latex/`, controlled by
  `paper/targets/nycu_thesis/README.md`.

## Do Not

- Do not hand-edit generated PDFs, `.aux`, `.bbl`, `.toc`, or figure binaries
  unless the task is explicitly about generated artifacts.
- Do not place new conference or thesis-specific files directly at `paper/`
  root. Create or use `paper/targets/<target>/`.
- Do not let a reviewer simulation or subagent opinion become a manuscript claim
  until it is distilled into `notes/` or the target's `source_map.md`.
- Do not cite new papers without verification.
- Do not mix Spatial-only claims with combined Spatial+Object claims.
